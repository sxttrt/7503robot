# 单模块测试说明

做完一个模块就可以先测，不需要等整车完成。现有 ROS 接口可直接观察或调用；本页提供手动测试入口，暂未提供一键验收工具。

## 上板测试与联系

模块完成后需要在实机上测试。需要取用板子、部署程序、烧录固件或现场联调时，在微信群里联系我（**刘承韬**）；开发或接口对接有问题，也可以在群里交流。

建议使用 **VS Code Remote-SSH** 连接树莓派，直接编辑代码、编译和运行测试。树莓派程序部署运行，ESP32 固件需要烧录。

## 单模块测试如何开始

1. 按 README 构建本工程，再构建你自己的 ROS 包。
2. 终端一只启动待测模块及它需要的驱动，不启动主状态机，不启动整套模拟。
3. 终端二设置相同通信域、加载两个工作区后，执行下面的观察／调用命令。

两个终端都要设置：

```bash
source /opt/ros/jazzy/setup.bash
source ~/7503robot_ws/install/setup.bash
# 自己的模块在另一工作区时，再加载该工作区的 install/setup.bash。
export ROS_DOMAIN_ID=42
# 本说明用于同一台电脑测试；跨电脑联调需统一发现设置。
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
export ROS_STATIC_PEERS=''
```

本页使用默认实机名称 `/team2/robot/...`。自己的节点需使用命名空间 `team2/robot`，或通过重映射提供对应接口。相对名称和类型以《模块接口说明》及 `interfaces.yaml` 为准。

## 按任务选择测试

| 模块 | 怎么发起测试 | 应观察什么 |
|---|---|---|
| 相机与 QR | 展示实际标签并观察 `qr/detections` | 完整 raw 字符串、实际图像时间戳；无 QR 时为空数组 |
| 导航 | 给 `navigate_to_pose` 发一个实测地图目标 | 目标接受、过程反馈、实际到点并停止、最终结果 |
| 对准进入／退出 | 给 `docking/execute` 发 ENTER 或 EXIT | 进入后 ready_to_lift，退出后 exited；不是看到 QR 就成功 |
| 升降 | 调 `lift/set_up`，true 升、false 降 | 机构实际到位后才返回成功；随后有新鲜状态反馈 |
| 健康与停止 | 观察 `robot/status`，调 `safety/stop` | 时间戳、真实模块状态、实际静止；停止后当前动作最终结束 |

下面命令会调用真实模块。导航位姿、货架完整 QR 和机构初始条件需要按实际测试填写。不要在主状态机也控制同一硬件时手动发动作。

### QR：直接看输出

```bash
ros2 topic echo /team2/robot/qr/detections
```

核对 JSON 字段见 [模块接口说明](模块接口说明.md)。分别试正确标签、其他标签、没有标签。单独观察只证明消息输出；主状态机的三帧确认、过期帧拒绝等逻辑另有测试。

### 导航：发一个目标

```bash
# x=1、y=0 只是消息格式示例，先换成可达的实测位置。
# stamp 省略时为零；服务端需按当前地图目标处理。
ros2 action send_goal /team2/robot/navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.0, y: 0.0, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}" --feedback
```

地图、定位、TF 和底盘驱动由导航模块准备。需观察最终成功状态和导航错误码为零，并核实实物到点停止。还应验证不可达目标和中途取消；取消测试需模块自己的客户端或 ROS Action 客户端支持，终端退出不等于服务器停止动作。

### 对准：发进入或退出请求

```bash
# 先把 expected_qr 换成本队 A 货架的完整值，确认当前满足进入测试条件。
ros2 action send_goal /team2/robot/docking/execute mission_interfaces/action/Dock \
  "{request_id: test_A_enter_001, operation: ENTER, rack_id: A, expected_qr: 'RACKA_实际后缀', max_duration_sec: 15.0}" --feedback
```

退出测试使用新的 request_id，将 operation 改为 EXIT。实际放下完成并满足退出条件后再测试。ENTER 成功要求 `success=true` 和 `ready_to_lift=true`；EXIT 成功要求 `success=true` 和 `exited=true`，同时 ROS 动作最终状态为成功。

### 升降：升起、放下并核对反馈

```bash
# 在另一个终端持续查看实际状态。
ros2 topic echo /team2/robot/robot/status

# 以下两个调用按测试步骤分别执行，不要同时发送。
ros2 service call /team2/robot/lift/set_up std_srvs/srv/SetBool '{data: true}'
ros2 service call /team2/robot/lift/set_up std_srvs/srv/SetBool '{data: false}'
```

成功响应代表动作已完成。健康状态应报告该次动作之后的新鲜时间戳、方向一致的 `lift_is_up` 和反馈来源。若聚合健康发布者尚未完成，先验证自己模块的实际到位反馈，交接时标注暂未验证完整状态机握手。

### 停止：验证实际停止结果

```bash
ros2 service call /team2/robot/safety/stop std_srvs/srv/Trigger '{}'
ros2 topic echo /team2/robot/robot/status
```

同时核实底盘实际停止、动作客户端得到终止结果，升降按机械方案停止或保持。只收到 success 响应不能证明所有动作已停止。

## 单模块测试之后

单模块通过之后，再补齐实机目标配置和所需健康／停止接口，按 [运行说明](运行说明.md)做完整主流程联调。

本页命令语法参考 ROS 2 Jazzy 官方源码：[动作调用](https://github.com/ros2/ros2cli/blob/jazzy/ros2action/ros2action/verb/send_goal.py)、[服务调用](https://github.com/ros2/ros2cli/blob/jazzy/ros2service/ros2service/verb/call.py)。命令帮助已在项目树莓派环境中核对；真实模块尚未提供，本页未执行实物动作测试。
