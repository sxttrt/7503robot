# 部署、依赖与电脑—树莓派联合验证

电脑运行 Gazebo；树莓派运行实机上位机软件。先用电脑传来的仿真雷达/时钟和虚拟执行反馈验证上位机，再接真实雷达检查定位，最后接真实底盘在场地中测试。树莓派不需要安装或运行 Gazebo。

## 包与依赖

支持 Ubuntu 24.04、ROS 2 Jazzy。树莓派使用对应的64位 ARM64 系统并在目标机编译；电脑的 x86 install 不能复制去当作树莓派安装。

| 包 | 用途 | 部署位置 |
|---|---|---|
| mission_interfaces | NavigateToPoint、Dock、TrackPath 动作定义 | 两端 |
| mission_manager | 状态机、框架适配器、QR 测试发布器 | 两端安装；任务在树莓派运行 |
| robot_navigation | 定位、共享算法、规划、进退架、跟踪、速度 JSON | 两端安装；导航在树莓派运行 |
| robot_bringup | 参数与启动文件 | 两端 |
| rack_simulation | Gazebo 插件、执行桥、场景、世界、纹理和仿真管理 | 仅电脑 |

依赖已声明在各包 package.xml，安装以 rosdep 为准：

| 场景 | 主要系统依赖 |
|---|---|
| 实机与树莓派联合验证端 | rclpy、消息与动作库、TF2、ament 索引、launch、Nav2 costmap/planner/Navfn/lifecycle、NumPy、PyYAML、setuptools |
| 电脑联合仿真 | 上述依赖，以及 Gazebo Harmonic vendor 包、ros_gz_sim/bridge/interfaces、OpenCV、qrcode、Pillow |
| 电脑普通旧版货架仿真 | 额外使用 slam_toolbox、nav2_controller、nav2_mppi_controller；已由 rack_simulation 声明 |

Gazebo 插件明确支持 Harmonic：gz-sim8、gz-transport13、gz-plugin2。安装其他 Gazebo 大版本不属于当前支持范围，不能只改一个库名就宣称兼容。ROS Jazzy 的默认 Gazebo 配对是 Harmonic，参见 [官方安装说明](https://gazebosim.org/docs/harmonic/ros_installation/)。完整 rack_simulation 安装同时满足两种电脑仿真入口；树莓派的四包依赖清单不包含 Gazebo、OpenCV、qrcode 或 slam_toolbox。

两端在已安装 ROS Jazzy、已配置 ROS apt 源的前提下准备构建工具：

```bash
sudo apt update
sudo apt install -y build-essential cmake git python3-colcon-common-extensions python3-rosdep
```

首次尚未初始化 rosdep 的机器执行 sudo rosdep init；已经初始化过就跳过这一步，然后更新用户缓存：

```bash
sudo rosdep init
rosdep update --rosdistro jazzy
```

rosdep 会从 package.xml 解析系统依赖；并非“只需要安装四个系统包”。参考 [ROS 官方 rosdep 教程](https://docs.ros.org/en/jazzy/Tutorials/Intermediate/Rosdep.html)。

## 树莓派只复制 src 即可

把以下四个目录复制到任意工作区的 src/ 下，不需要仓库外层文件、navigation 目录、.7503robot-project 或 .build-root：

```text
~/7503robot_ws/src/
  mission_interfaces/
  mission_manager/
  robot_navigation/
  robot_bringup/
```

也可以复制完整 src，但下列命令仅安装/构建四个实机包，不会构建 rack_simulation：

```bash
cd ~/7503robot_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src/mission_interfaces src/mission_manager src/robot_navigation src/robot_bringup --ignore-src --rosdistro jazzy -y
colcon build --base-paths src --symlink-install --packages-select mission_interfaces mission_manager robot_navigation robot_bringup
source install/setup.bash
ros2 run robot_navigation check_dependencies --profile robot
```

共享算法已安装为 robot_navigation.algorithms；默认实机参数安装在 robot_navigation/share 下，通过 ament 包索引读取。状态机和导航不再在启动时查找源仓库根目录。package.xml 的 Python 构建依赖使用可解析的 python3-setuptools，构建类型仍是 ament_python。

开发者可在完整源码目录运行 python3 tools/verify_src_only_build.py 复查这一契约：工具仅复制四包到临时目录编译，隐藏复制的源码，再阻止仿真模块导入并加载实机模块/启动描述；不会初始化 ROS 节点。构建记录保留在打印出的临时目录中。

## 电脑侧安装与启动

电脑使用完整源码或包含五个包的 src 工作区，安装全部依赖并编译：

```bash
cd ~/7503robot_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src --rosdistro jazzy -y
colcon build --base-paths src --symlink-install
source install/setup.bash
ros2 run robot_navigation check_dependencies --profile hybrid
```

完整源码目录也可用 bash scripts/build.sh 构建。check_dependencies 仅检查依赖，不启动节点；仿真运行器还会在生成世界之前自动检查依赖，缺包时一次列出缺项。

## 第一阶段：电脑 Gazebo → 树莓派上位机

两端使用同一提交版本。各自在已经 source ROS 和本机 install 的终端中设置：

```bash
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
export ROS_LOCALHOST_ONLY=0
```

电脑运行：

```bash
ros2 run rack_simulation run_simulation --hybrid --remote-backend
# 完整项目也可用：bash scripts/run_rack_hybrid.sh --remote-backend
```

树莓派运行：

```bash
ros2 launch robot_bringup rack_hybrid_backend.launch.py
```

数据流：

```text
电脑 Gazebo → /scan、/clock、虚拟底盘/升降反馈 → 树莓派
树莓派：定位 → /odom/TF → costmap → 规划/进退架 → TrackPath → /cmd_vel
树莓派 /cmd_vel → 电脑虚拟底盘执行 → 下一帧雷达与执行反馈
树莓派状态机 → 电脑模拟升降接口；QR 测试发布器替代视觉输入
```

电脑前端只启动模拟执行桥和误差评估，树莓派后端启动定位、costmap、导航、进退架、跟踪、JSON 和状态机。没有第二份导航控制器。电脑输出“前端已启动”不代表树莓派定位和任务已就绪，应查看树莓派日志和 mission/status。

树莓派后端使用 use_sim_time=true 和 simulation_only 的测试配置；这是实机代码的测试输入，不会改写真实 calibration_verified、QR 或点位配置。修改电脑场景后，将电脑启动输出中 framework_config 目录同步到树莓派，再指定：

```bash
ros2 launch robot_bringup rack_hybrid_backend.launch.py config_dir:=/你的路径/framework_config
```

任一端在对应等待阶段用脚本触发扫码，双方命令终端必须同用上述通信域：

```bash
ros2 run mission_manager publish_qr_result START
ros2 run mission_manager publish_qr_result RACKA_XXXX  # 后续 B/C/D 同理
ros2 run mission_manager publish_qr_result END
```

先确认树莓派能收到 /clock 和 /scan，再检查 /odom、/team2/sim/navigation/path、/cmd_vel 与 /team2/sim/base/cmd_vel_json。跨机器需要 DDS 双向连通；WSL2 默认 NAT 或防火墙可能阻挡发现，必要时按 [微软 WSL 网络说明](https://learn.microsoft.com/en-us/windows/wsl/networking) 配置可互通网络或适当的发现方案。单机离线测试不能证明双机网络已经连通。

停止：树莓派 Ctrl-C 结束后端；电脑执行 ros2 run rack_simulation stop_simulation。若用完整项目的 run_*.sh 启动，则用同一项目的 bash scripts/stop_rack_sim.sh 停止，以选中同一运行目录。仿真端和实物雷达不要同时向同一域的 /scan、/odom、TF 发布不同数据。

需要电脑独自运行全部联合验证时，使用 ros2 run rack_simulation run_simulation --hybrid（完整目录也可用 bash scripts/run_rack_hybrid.sh）。该入口组合的仍是同一份前端与后端启动文件。普通历史仿真使用 ros2 run rack_simulation run_simulation，只有电脑需要它。

## 第二、三阶段：真实雷达，再真实场地

退出联合仿真后，树莓派使用实机入口：

```bash
ros2 launch robot_bringup robot.launch.py
# 全部实物配置和模块就绪后才带状态机：
ros2 launch robot_bringup robot.launch.py start_mission:=true
```

实机默认域42、use_sim_time=false。第一条默认只启动上位机，雷达/ESP32/QR/平台驱动由对应模块提供。没有实测标定时原始扫描可以检查，但本包不会输出假定有效的定位或放行导航。

待实测文件：src/robot_navigation/config/navigation_robot.yaml（calibration_verified 仍 false）；src/robot_bringup/config/targets_robot.yaml（QR 仍 null）；src/robot_bringup/config/navigation_points_robot.yaml（点位、投放点、架口几何仍 null）。修改后重新构建，或用 robot.launch.py 的 navigation_file、targets_file、points_file 参数指定已标定文件。雷达倒装和自体回波仍需结合真实驱动与安装测量适配。

默认日志在 ~/.ros/7503robot/runtime_logs，可用 ROBOT_RUNTIME_DIR 指定。完整项目的 run_*.sh 将日志保存在本项目 runtime_logs。Gazebo 运行器将只读安装资源复制到该日志目录下的 simulation 子目录，再生成世界、纹理和测试配置；不会向源码或安装目录写入运行产物。

实物轮子空转可用于检查编码器轮速与指令跟踪，但仿真导航仍使用虚拟小车位置。空转阶段的实际编码器反馈单独记录；实际位移、打滑和避障效果留到真实场地低速测试。
