# DASE7503 第二队任务系统

本工程负责完整任务状态机、模块接口和模拟程序。固定按 **A → B → C → D** 搬运；比赛从有效确认 `START` 后计时三分钟。当前不知道第二队的真实二维码，实机配置保留为空，不猜测后缀。

项目可在安装了 ROS 2 Jazzy 的 Ubuntu 24.04 电脑或树莓派上构建和运行模拟。下文统一使用 `~/7503robot_ws` 作为工作区。下载代码和编辑不需要机器人硬件；多台电脑上的副本需要通过 Git 提交和拉取保持同步。

第一次下载及安装依赖的步骤见仓库根目录 README。下面的运行命令适用于已经完成构建的工作区；实机接入仍需补齐目标数据和真实模块。

## 先运行模拟

在已经构建好工作区的 Ubuntu 终端、树莓派终端或 SSH 终端执行：

```bash
cd ~/7503robot_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch robot_bringup simulation.launch.py
```

默认模拟自动启用并生成虚拟 `START`，随后搬运 A、B、C、D。模拟目标的 `SIMTEAM2` 后缀完全虚构。终端会显示状态转换，完成后状态为 `FINISHED`。模拟节点保持运行供查看，按 `Ctrl+C` 退出。

查看状态时，在同一台电脑的另一个终端使用与模拟相同的通信域：

```bash
source /opt/ros/jazzy/setup.bash
source ~/7503robot_ws/install/setup.bash
export ROS_DOMAIN_ID=62
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 topic echo /team2/sim/mission/status
```

模拟使用独立通信域 62、命名空间 `/team2/sim` 和本机发现。不会发布真实运动速度，也不会访问串口、电机、雷达或相机。

## 人工启用和停止

可关闭模拟自动启用：

```bash
ros2 launch robot_bringup simulation.launch.py auto_arm:=false
```

在另一个已设置通信域 62 的终端调用：

```bash
# 启用只进入等待 START，尚未开始比赛计时。
ros2 service call /team2/sim/mission/arm std_srvs/srv/Trigger '{}'

# 响应表示请求已接收或确认正在进行；不表示实际已经静止。
ros2 service call /team2/sim/mission/stop std_srvs/srv/Trigger '{}'
```

收到简单在线反馈且接口可用即可启用，不要求静止或升降测量状态。初始摆放由现场人员完成。本轮结束后重启节点开始新一轮。

`mission/stop` 只接收停止意图，随后主程序调用执行端 `safety/stop`；执行端成功响应即表示停止完成。停止失败或超时后可再次调用 `mission/stop`，原故障原因保留，最新结果显示在 `stop.status`。

不再等待令牌、二次静止反馈或旧动作回执。退出时尚未确认停止会再尝试一次，等待有时限。正常搬运期间不需要人工逐步确认。

## 故障模拟

```bash
# 导航第一次失败，停止确认后重试，最后完成四个货架。
ros2 launch robot_bringup simulation.launch.py scenario:=navigation_fail_once

# 模拟携货导航失败，停机并保留已携货状态，不放下也不开始 B。
ros2 launch robot_bringup simulation.launch.py scenario:=delivery_navigation_failure

# 模拟货架二维码来自其他队伍，等待超时并有限重试后进入故障。
ros2 launch robot_bringup simulation.launch.py scenario:=wrong_rack_qr
```

全部场景及中文说明在 `src/robot_bringup/config/mock_scenarios.yaml`。

## 源码怎么找

| 位置 | 内容 |
|---|---|
| `src/mission_manager/mission_manager/state_machine.py` | 固定货架顺序、状态、计时、重试、完成记录和货物状态 |
| `src/mission_manager/mission_manager/mission_node.py` | ROS 节点、启用与停止服务、日志和状态发布 |
| `src/mission_manager/mission_manager/adapters/` | 导航、QR、对准、升降、健康与停止接口 |
| `src/mission_manager/mission_manager/mock_modules.py` | 使用同样 ROS 接口的模拟服务端 |
| `src/mission_interfaces/action/Dock.action` | 队友对准服务端共用的动作类型 |
| `src/robot_bringup/config/` | 带中文注释的流程、接口、模拟及实机配置 |
| `src/robot_bringup/launch/` | 模拟和实机启动入口 |
| `docs/给队友看/模块接口说明.md` | 给队友的接口契约与接入方法，不列负责人 |
| `docs/给队友看/任务流程说明.md` | 正常任务流程、失败处理和实机联调事项 |
| `runtime_logs/` | 树莓派实际运行时生成的状态转换日志 |

`build/`、`install/` 和 `log/` 是编译工具生成的目录，配置和源码位于 `src/`。

## 修改后重新构建

首次构建及修改动作定义、依赖或启动文件后，在运行工作区的电脑上执行：

```bash
cd ~/7503robot_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

依赖包括 ROS 2 Jazzy 基础版、colcon、Python YAML 和本工程生成的 mission_interfaces 动作。任务框架不依赖 Nav2 消息；队友若内部使用 Nav2，自行准备相应导航依赖。

## 实机接入前必须补齐

1. 第二队 A、B、C、D 的完整 QR。队伍编号 2 不能推导二维码后缀。
2. 导航模块能处理 A、B、C、D、DROP_OFF 五个点位名；对应地图、坐标和朝向由该模块维护，不填入主程序配置。
3. 队友的真实导航、二维码、对准、升降、停止及健康状态模块。
4. 对准进入的实际可托举条件、退出条件和底盘控制权切换。
5. 升降服务完成后返回结果，不能只代表收到命令；无需额外反馈来源字段。

导航使用 `mission_interfaces/action/NavigateToPoint`，只接收 `target_id`；升降使用标准 `std_srvs/srv/SetBool`；在线消息仅需 `ready` 与 `fault`。旧版本的安全令牌和健康状态版本字段不再需要。默认导航到目标区后直接放下。更新源码和配置后重新构建，详见 [模块接口说明](模块接口说明.md)。

```bash
# 当前实机配置未填写，此命令会报出缺失项并退出，不会启动模拟模块。
ros2 launch robot_bringup robot.launch.py
```

实机默认通信域 42，命名空间 `/team2/robot`，必须人工启用。底盘看门狗、机械保持和硬件急停由真实控制模块实现，本工程提供调度、超时、取消与停止调用。模拟通过不能替代实机搬运验收。
