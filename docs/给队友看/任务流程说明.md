# 任务流程说明

## 正常流程

```text
IDLE 待启用
 → WAIT_START 等待有效 START
 → NAV_RACK 前往固定顺序的当前货架
 → WAIT_RACK_QR 确认该货架完整二维码
 → DOCK_ENTER 对准并进入，确认可托举
 → LIFT_UP 升起并确认
 → NAV_END 携货前往目标区
 → WAIT_END_QR 确认 END（配置可关闭）
 → LIFT_DOWN 放下并确认，记录已交付
 → DOCK_EXIT 退出并确认，记录本轮完成
 → NAV_RACK 前往下一个固定货架
 → 四个全部完成后 STOPPING 停止确认
 → FINISHED 结束
```

比赛时间到也经停止确认后进入 `FINISHED`，但未完成的货架不会记录为完成。人工停止进入 `STOPPED`，失败进入 `FAULT`。如果已经因为故障或人工停止而停机，随后时间到不会把它改写成正常结束。三个终态均不自动恢复；程序退出或再次人工停止会撤销已经安排的自动重试。

## 故障策略

| 场景 | 默认处理 |
|---|---|
| 空载前往货架失败 | 停止确认后额外重试一次，仍失败则故障，不跳过货架 |
| 货架 QR 扫不到或错误 | 清空确认计数并重新等待，最多额外重试两次 |
| 对准失败或未确认可托举 | 不升降，停止并故障 |
| 升起或放下失败 | 货物状态保留 UNKNOWN，停止，不猜测结果 |
| 携货导航失败 | 保留 UP，不放下、不进入下一货架 |
| 退出失败 | 保留已放下及已交付记录，不记录完整闭环 |
| 导航或对准成功但未确认实际静止 | 等待新鲜静止反馈，超时走停止与故障处理 |
| 搬运中机构意外下降／空载时意外升起 | 货物状态改为 UNKNOWN，停止并等待人工检查 |
| 日志、状态发布或通信回调异常 | 撤销重试并请求停止，不继续发送新动作 |
| 必需模块断联 | 停止；无法确认停止时仍故障，不重试 |
| 停止超时或失败 | 故障，停止发起任何新动作 |
| 故障后人工再次停止 | 重新请求物理停止，保留原故障和原因，不恢复任务 |
| 扫码等待时仍在运动／下一动作前未静止 | 不进入对准或升降，停止并故障 |
| 停机期间或结束后机构状态意外变化 | 携货记录改为 UNKNOWN，取消待执行重试并故障 |
| 时间到 | 取消当前请求、停止移动、保持机构的安全状态 |
| 旧反馈到达 | 请求编号不匹配，忽略，不推进当前流程 |

自动 QR 重试只重新观察，尚未实现主动移动扫码位置；局部恢复路径需要对准模块接入后再扩展。

停止命令先于日志和状态显示发出，避免记录耗时挡住停机。再次请求停止只重新检查是否已停下，三个终态仍不能重新启用本轮任务。
