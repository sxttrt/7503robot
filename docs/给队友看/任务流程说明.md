# 任务流程说明（简化版）

```text
启用 → 等待 START → 开始三分钟计时
 → 发点位名 A／B／C／D，导航模块自行到相应货架
 → 识别该货架完整 QR
 → 对准并进入
 → 升起
 → 发点位名 DROP_OFF，导航模块自行到放置区
 → 直接放下（默认不再扫码 END）
 → 退出货架
 → 下一个货架；四个完成后停止并结束
```

每一步都由主程序下发任务，模块完成并停止后返回成功，主程序直接进入下一步；失败返回原因。没有逐步人工确认，不要求安全令牌或二次到位状态。

| 情况 | 主程序处理 |
|---|---|
| 空载导航到货架失败／超时 | 请求停止，成功后最多额外重试一次；仍失败则故障，不跳过货架 |
| 货架 QR 扫不到／扫错 | 等待超时后停止并重新观察，最多额外重试两次 |
| 对准、升降、携货导航、退出失败 | 停止并进入故障，不自动跳过或发送反方向动作 |
| 在线反馈中断／报告故障 | 请求停止，结束自动流程 |
| 三分钟到 | 停止新增任务，请求停止后结束；未完成货架不记录完成 |
| 人工停止 | 取消当前任务，请求执行模块停止 |
| 停止失败／超时 | 显示未确认结果，进入故障；可以人工再请求停止 |
| 程序退出时停止未确认 | 再做一次有时限的停止尝试 |
| 旧动作结果迟到 | 不影响当前任务，按原请求关联自动忽略 |

`delivered` 在放下成功后记录，`completed` 在退出成功后记录。`cargo` 根据升降结果记录 EMPTY／UP／UNKNOWN，不额外要求到位传感器反馈。

默认 `confirm_end_qr: false`。保留可选 END 开关，仅在组内明确需要时改为 true；默认流程只信任导航报告目标区到达。

实机启动后启用一次，进入 FINISHED／STOPPED／FAULT 后重启开始新一轮。实机 QR 需填写任务配置；地图点位由导航模块自行维护，硬件动作由对应模块接入。本说明是组内流程约定，计分以老师现场判定为准。
