# 单目录项目与换电脑

只需要完整的 7503robot-main 源码目录；其绝对路径和用户名不限。原外部 rack_v3 已合并为 navigation/，不参与现行启动。

```text
7503robot-main/
  .7503robot-project       项目定位标记，复制时保留
  src/                    状态机、接口包、启动配置
  navigation/             雷达定位、规划、仿真驱动、配置、资源与离线测试
  scripts/                build.sh / run_rack_sim.sh / stop_rack_sim.sh / QR测试
  tools/                  目标配置生成
  docs/                   团队接口与交接说明
  firmware/               ESP32队友实现入口
```

在安装 ROS 2 Jazzy、Gazebo Harmonic 及相关依赖的 Ubuntu 环境，进入复制后的项目根目录：

```bash
bash scripts/build.sh
bash scripts/run_rack_sim.sh
# 停止本项目：
bash scripts/stop_rack_sim.sh
```

build.sh 在目录改变时将旧 build/install 保留到 .build_cache_backups/，然后重新构建；生成输出中的绝对路径属于当前电脑，不能直接用于另一台电脑。run_rack_sim.sh 会拒绝加载另一位置的旧构建输出。
源码、场景、纹理和配置均在项目内。导航日志在 navigation/log/run_*/，状态机日志在 runtime_logs/framework/。纹理通过世界文件相对路径解析，GZ_SIM_RESOURCE_PATH 也由项目启动脚本设置，世界生成不会写入某台电脑的用户路径。
ROS安装路径 /opt/ros/jazzy 是软件依赖，不是项目位置。底盘硬件串口、雷达设备及实测参数仍需在对应电脑配置，项目迁移不会自动替代硬件标定。
历史外部项目保留作备份；无需随项目交付。integration_backups、旧日志和 .build_cache_backups 属历史数据，构建启动不引用它们。


Gazebo 导航运行依赖：ROS 2 Jazzy、Gazebo Harmonic、ros_gz_bridge/ros_gz_interfaces、Nav2（控制与规划节点用于 costmap）、slam_toolbox；Python 需要 numpy、OpenCV、qrcode、yaml。这些是系统软件依赖，不是另一份项目源码。当前电脑已经具备；新电脑先按对应 Ubuntu/ROS 安装方式准备，再运行项目 build.sh。


实机新增 `src/robot_navigation` 包，统一入口 `scripts/run_robot.sh`，配置在 `src/robot_bringup/config/{navigation_robot,costmap_robot,mission_robot,targets_robot}.yaml`。仍只需要整个项目目录；无需复制外部定位导航文件。


Gazebo 仿真新增 `src/rack_simulation`（C++ 仿真步执行插件），使用 ROS Jazzy 的
gz_sim_vendor／gz_transport_vendor／gz_plugin_vendor 开发依赖。完整构建会编译该插件，
install 环境钩子设置 GZ_SIM_SYSTEM_PLUGIN_PATH，项目位置不硬编码。
树莓派只做实机定位导航与框架时执行 `bash scripts/build.sh --robot` 跳过此 Gazebo 包；
实机 launch 不启动插件、仿真驱动或仿真平台。
