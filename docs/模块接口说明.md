# 模块接口说明：第二队

这是组内代码契约，接口名称和对准动作属于工程提案，不能当作老师指定的 API。流程固定 A→B→C→D；QR 后缀需拿到第二队标签后填写。

## 通信约定

原 mock 模拟：通信域 202，命名空间 `/team2/sim`；rack_v3 入口继承运行环境，默认通信域 0，以启动脚本打印值为准。实机：默认通信域 42，命名空间 `/team2/robot`。所有模块必须使用相同通信域；同名节点同时运行会冲突，接入真实模块时不能同时保留对应模拟服务端。

`interfaces.yaml` 使用相对名称。例如 `navigate_to_pose` 在实机完整名称为 `/team2/robot/navigate_to_pose`。名称可以改配置，消息类型或动作完成语义改变则修改适配代码。

| 任务 | 名称 | 类型 | 完成条件 |
|---|---|---|---|
| 前往货架或目标区 | `navigate_to_pose` | `nav2_msgs/action/NavigateToPose` | 当前目标最终状态成功，导航错误码为零 |
| QR 观察 | `qr/detections` | `std_msgs/msg/String` | 新鲜且不同的图像帧连续确认完整预期 QR |
| 对准进入或退出 | `docking/execute` | `mission_interfaces/action/Dock` | 动作成功，进入时明确可托举，退出时明确已脱离 |
| 升降 | `lift/set_up` | `std_srvs/srv/SetBool` | 响应成功代表动作完成，再与新鲜状态核对 |
| 升降参考状态 | `lift/is_up` | `std_msgs/msg/Bool` | 只展示，不能单独推进状态机 |
| 模块健康状态 | `robot/status` | `std_msgs/msg/String` | 数据有时间戳，模块正常；具体字段见下文 |
| 停止所有动作 | `safety/stop` | `std_srvs/srv/Trigger` | 成功响应、新鲜静止状态及旧动作最终结束同时满足 |

## 导航

目标位姿在配置的 `frame_id` 中，默认 `map`；rack_v3 仿真入口也统一采用 `map`，内部控制通过 TF 转换为 `odom`，对外 Path 同样是 `map`。位置单位米，朝向在配置中用弧度，适配器转换成四元数。速度限幅、避障、里程计和 TF 由真实导航与底盘模块提供，状态机不计算这些内容。

必须支持取消。即使服务端很晚才接受旧目标，客户端也会立即取消它。在得到旧目标最终结果或拒绝之前，不会开始新的运动。导航成功需包含实际到达并停止的语义，距离反馈本身不能替代完成结果。

## QR 数据

可接入现有 `camera_qr/qr_node.py` 的 `/qr/detections`。最小 JSON 如下：

```json
{
  "image_stamp": {"sec": 1791450000, "nanosec": 100000000},
  "status": "ok",
  "detections": [{"raw": "RACKA_实际后缀"}]
}
```

上例时间戳只是字段示意，发送时必须使用实际图像时间；字符串也要替换成本队完整值。没有二维码时发布 `detections: []`，解码异常时 `status` 使用其他值。主程序忽略额外字段，因此角点、图像尺寸、中心误差可以保留。

图像时间与主节点 ROS 时钟应一致。过期、未来偏差过大、前一个观察窗口的图像、重复帧、其他队后缀都会被拒绝。当前默认采用一条上游已确认的识别结果（qr_confirm_frames=1）；可配置多帧确认。空观察会清空计数。QR 身份正确不等于可以托举。

已有节点默认发布全局名称时，可重映射：

```bash
# 仅演示重映射语法；真实运行还需安装视觉依赖并启动相机图像节点。
python3 ~/camera_qr/qr_node.py --ros-args \
  -r /qr/detections:=/team2/robot/qr/detections
```

实机相机 ROS 驱动及识别算法仍由视觉模块提供。rack_v3 联调桥可选内置 Gazebo 图像解码，但默认关闭，并直接使用本节的外部 QR 结果；ENTER 不检查私有图像识别缓存。

## 对准进入与退出

服务端编译时依赖 `mission_interfaces`，引用 `Dock` 动作。目标包括 `request_id`、`operation`、`rack_id`、`expected_qr`、`max_duration_sec`。

* `ENTER`：确认完整目标 QR 后，根据视觉或其他测量做局部对准并进入货架下方。只有机械位置满足托举条件，才能返回 `success=true`、`ready_to_lift=true`。
* `EXIT`：放下完成之后脱离货架，必须返回 `success=true`、`exited=true`。
* 取消或超时：停止局部运动，再返回动作的取消或失败结果。服务端也应独立执行超时和速度命令看门狗。

本版扫码失败只重新观察，不自行移动。若需要重新调整扫码位置，之后可扩展该动作的操作类型并实现恢复路径，不能让状态机随意发布速度。

## 升降

`SetBool.Request.data=true` 表示升，`false` 表示降。第一版配置固定 `response_means_completed`，`Response.success=true` 必须在动作完成后返回。如果只是接受命令，请先改写服务端或扩展适配器，不能直接连接。

健康状态中的 `lift_is_up` 到位后是布尔值，运动中或未知时为 null；提供 `lift_settled` 时必须为 true 才确认完成。`lift_state_source` 为 `measured`（实际测量）或 `estimated`（按动作推定）。成功响应还要等待本次请求之后生成的新鲜状态，并且方向一致。默认配置禁止推定状态。

`lift/is_up` 没有时间戳和请求编号，所以只作为参考。仅有一个旧的 true，不能证明当前升起完成。Service 没有 Action 的取消能力，停止接口必须能中断或保持升降；客户端超时后不发送相反命令，并等待旧服务结束。

## 健康状态与停止

真实集成需要提供聚合健康发布者。不得未经检查把所有模块写成 true。建议 5～10 Hz 发布；字段示例：

```json
{
  "schema_version": 1,
  "stamp": {"sec": 1791450000, "nanosec": 100000000},
  "modules": {"navigation": true, "qr": true, "docking": true, "lift": true, "base": true},
  "stopped": true,
  "lift_is_up": false,
  "lift_state_source": "measured",
  "fault": ""
}
```

`stopped` 代表实际停止，不能只代表发了零速度。根据实际控制器反馈及必要的里程计判断；机构仍有货物时停止应保持安全托举，不自动放下。

`safety/stop` 要协调导航、对准、升降和底盘。状态机也会取消当前 Action。停止请求之后必须产生新状态，旧动作必须结束，才允许重试；任何一项缺失都进入故障，不冒险继续。

底盘应独立处理速度命令超时并限制速度；导航和对准必须串行取得底盘控制权。网络或主程序退出时，底层保护仍需有效。硬件反馈和控制程序尚未接入，当前这些能力仅由模拟服务端演示。

## 主程序的对外状态

`mission/status` 为 JSON，包含 `state`、`rack`、`request_id`、`cargo`、`remaining_sec`、`completed`、`delivered`、`attempt`、`reason`、`ready_to_arm`、`progress`。

`cargo`：`EMPTY` 未携货或确认放下；`UP` 确认托举；`UNKNOWN` 升降尚未确认或失败。`delivered` 在目标区确认放下后更新；`completed` 需再完成退出才更新。两者是内部执行记录，最终比赛计分仍依据老师的现场判定。

`mission/arm` 和 `mission/stop` 使用 `Trigger`。停止服务的立即响应只表示请求已接收，必须观察后续状态；故障后不会自动启用或跳过货架。

当前 rack_v3 入口为全自动动作推进；START、货架码及最终 END 都通过 QR 结果确认，不使用 `/rack/next`。底盘已实现的上位机命令接口为 `/cmd_vel`（geometry_msgs/Twist，base_link 速度）；ESP32 通信和四轮伺服待底盘组实现，字段及轮速解算详见 README。


现行仿真导航坐标由固定墙雷达定位提供，map→odom 为静态恒等关系；SLAM 仅扫描建图，transform_publish_period=0，不能同时发布第二条导航 TF。实机更换定位算法时应关闭仿真静态关系，由实机定位器单独提供 map→odom。
地图由 published_costmap_cache.py 缓存 global_costmap/costmap_raw 的完整发布快照，实时导航不轮询 GetCostmap 服务。navigation_diagnostic 与 costmap_pipeline 纳入 robot/status 诊断；过期地图不能用于行驶。举放完成必须确认当前目标、实测关节位置和载荷状态，不能仅凭旧 settled 状态成功。
