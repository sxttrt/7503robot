# 流程与测试说明

## 正常流程

```text
IDLE 待启用
 → WAIT_START 等待有效 START
 → NAV_RACK 前往固定顺序的当前货架
 → WAIT_RACK_QR 确认该货架完整二维码
 → DOCK_ENTER 对准并进入，确认可托举
 → LIFT_UP 升起并确认
 → NAV_END 携货前往目标区
 → WAIT_END_QR 确认 END（配置可关闭）
 → LIFT_DOWN 放下并确认，记录已交付
 → DOCK_EXIT 退出并确认，记录本轮完成
 → NAV_RACK 前往下一个固定货架
 → 四个全部完成后 STOPPING 停止确认
 → FINISHED 结束
```

比赛时间到也经停止确认后进入 `FINISHED`，但未完成的货架不会记录为完成。人工停止进入 `STOPPED`，失败进入 `FAULT`。三个终态均不自动恢复；程序退出或再次人工停止会撤销已经安排的自动重试。

## 故障策略

| 场景 | 默认处理 |
|---|---|
| 空载前往货架失败 | 停止确认后额外重试一次，仍失败则故障，不跳过货架 |
| 货架 QR 扫不到或错误 | 清空确认计数并重新等待，最多额外重试两次 |
| 对准失败或未确认可托举 | 不升降，停止并故障 |
| 升起或放下失败 | 货物状态保留 UNKNOWN，停止，不猜测结果 |
| 携货导航失败 | 保留 UP，不放下、不进入下一货架 |
| 退出失败 | 保留已放下及已交付记录，不记录完整闭环 |
| 必需模块断联 | 停止；无法确认停止时仍故障，不重试 |
| 停止超时或失败 | 故障，停止发起任何新动作 |
| 时间到 | 取消当前请求、停止移动、保持机构的安全状态 |
| 旧反馈到达 | 请求编号不匹配，忽略，不推进当前流程 |

自动 QR 重试只重新观察，尚未实现主动移动扫码位置；局部恢复路径需要对准模块接入后再扩展。

## 验证分层

纯流程验证用可控时钟和接口后端，验证固定顺序、超时、任务编号、取消、货物状态和实机配置检查。QR 与动作适配边界测试验证时间戳、不同帧、错误后缀及迟到目标接受。

ROS 集成验证实际启动主程序和模拟服务端，通过 Action、Service、Topic 传递信息。测试观察端先收到就绪状态再启用，避免 ROS 节点发现延迟导致漏掉第一货架的早期状态。

集成覆盖正常四货架、导航重试与失败、超时、错 QR、对准未就绪、升降异常、携货导航失败、放下及退出失败、断联、停止失败、取消迟到、接受迟到、比赛时间到和人工停止。

测试进程使用独立通信域 197，正常模拟使用 202。不能把测试临时目标或短超时用于实机。
